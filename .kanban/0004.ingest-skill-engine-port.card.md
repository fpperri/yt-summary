# Ingest skill: port the single-video engine into this plugin

When I share a YouTube URL, I want the plugin to fetch a timestamped transcript and save a clean source set to a configurable output directory, so I can build study material without the cortex instance being involved.

Inspiration (do not copy wholesale — implement what is in scope for a generic public plugin): `~/source/fpp/.cortex/tools/skills/ingest-video/` — its transcript fetcher (including the yt-dlp fallback) is more robust than this repo's `scripts/yt_transcript.py`; port it and retire the duplicate so exactly one fetcher exists.

Scope boundaries decided 2026-09-01:
- Output directory is a parameter (default under the working dir) — no `.cortex/inquiry/sources/` paths, no cortex frontmatter. Cortex's own ingest-video becomes a thin wrapper over this engine (that repoint is cortex work, not this card).
- No CA-bundle handling in the code at all: Python already honors the standard `SSL_CERT_FILE` / `REQUESTS_CA_BUNDLE` env vars. Ship only a doc line ("behind TLS inspection? point `SSL_CERT_FILE` at your proxy's root CA"). Never hardcode a bundle path, never ship a bundle file, and never fall back to disabling verification.
- Keep the repo's existing test discipline (pytest) — port or rewrite fetcher tests.

## Acceptance Criteria
- One transcript fetcher in the repo, with yt-dlp fallback; TLS-inspection setups covered by a doc line on standard env vars, no custom handling.
- Skill ingests a single video URL/id to a configurable directory; resumable (skips existing slugs).
- No cortex paths, personal paths, or personal manifests anywhere in the repo.
